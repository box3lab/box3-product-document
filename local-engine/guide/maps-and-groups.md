# 地图组与地图

地图组用于组织一套可以相互传送和共享组数据的地图。每个地图组必须有一个主地图，也可以包含多个副地图。

## 主地图

主地图是地图组的入口。玩家第一次进入地图组时，通常会进入主地图。

主地图可以承担：

- 大厅和出生区域
- 玩法选择
- 房间匹配
- 前往副地图的传送入口

删除主地图对应的地图组会影响整个地图组，应在删除前备份工程和游玩数据。

## 副地图

副地图适合用于独立关卡、战斗房间或其他场景。每张副地图拥有自己的地形、实体和脚本，可以与主地图共享地图组资源和组数据空间。

副地图可以使用与主地图相同的容器配置，也可以在“单个地图”模式下配置不同的资源组和运行方式。

## 地图 ID

地图 ID 是 Creator 和运行时识别地图的稳定标识。

需要绑定 CLI 工程、配置容器或排查日志时，应使用页面显示的地图 ID。

## 地图组配置与单图配置

| 模式 | 适用情况 |
| --- | --- |
| 地图组 | 主地图和所有副地图使用相同配置 |
| 单个地图 | 某些副地图需要独立资源或隔离方式 |

选择“单个地图”时，会展示地图组内的全部地图。没有副地图时，不需要额外显示展开入口。

## 传送与房间

从主地图传送到副地图时，可以进入已有房间，也可以创建新房间。测试地图组时至少检查：

- 首次进入主地图
- 主地图传送到每张副地图
- 多名玩家进入同一房间
- 创建多个独立房间
- 玩家退出后的房间状态
- 空闲超时后的运行时回收

## 发布前检查

- 主地图设置正确。
- 所有副地图可以正常打开。
- 传送目标使用正确地图 ID。
- 地图组资源完整。
- 服务端和客户端脚本可以编译。
- 多人房间和存档流程已经测试。

容器配置请阅读[容器与资源管理](/guide/maps-and-containers)。
