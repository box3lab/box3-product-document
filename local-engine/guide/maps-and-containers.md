# 容器与资源管理

在玩家管理后台的“容器管理”中配置地图运行方式、资源上限和空闲回收。

## 1. 选择配置范围

- **地图组**：主地图和所有副地图共用一份配置。
- **单个地图**：为主地图或副地图分别配置，适合资源需求不同的地图。

## 2. 选择运行方式

| 方式 | 适用场景 | 特点 |
| --- | --- | --- |
| 共享 Node | 开发测试、可信地图 | 启动快、开销低；隔离程度较低 |
| 独立 Docker | 需要更清晰隔离的地图 | 可单独限制资源；启动较慢、占用更多系统资源 |

独立容器按地图或房间运行，属于 `box-local-engine-runtime` Compose 项目。

## 3. 设置运行限制

配置可包括玩家上限、房间上限、空闲回收时间和资源组。资源组可设置 CPU、内存、服务端网络策略、进程数和出网带宽。

网络策略只限制服务端地图运行时，不会自动限制玩家浏览器中的客户端代码。没有单独选择资源组时，仍使用系统默认限制。

## 4. 应用和观察配置

1. 保存配置。
2. 在容器列表中观察 CPU 和内存使用量。
3. 修改运行方式或资源上限后，重启地图运行时使配置生效。
4. 地图无人并超过空闲回收时间后，运行时会自动销毁；玩家再次进入时会重新创建。

“销毁”会移除当前运行时容器，不会删除已安装的地图包。

## 排查独立容器

```bash
docker ps --filter label=com.docker.compose.project=box-local-engine-runtime
docker logs <容器名称>
```

如果后台没有显示已启动的容器，确认后台连接的是正确的 Docker Engine，并检查玩家服务是否能访问 Docker Socket。
