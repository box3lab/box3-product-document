# 地图运行与资源管理

地图需要运行后，玩家才能进入。首次开服先使用默认配置；遇到容量不足或需要隔离不同地图时，再调整这里。

## 在哪里查看

打开玩家管理后台的“**容器管理**”，查看地图是否运行，以及 CPU、内存和房间情况。

没有玩家时，地图可能还没启动或已经空闲回收；这不代表地图包被删除。玩家再次进入时会重新准备运行环境。

## 选择设置范围

- **地图组**：主地图和副地图使用一份设置，适合大多数情况。
- **单个地图**：为某张地图单独设置，适合关卡之间的资源需求不同。

## 选择运行方式

| 方式 | 适合情况 |
| --- | --- |
| 共享 Node | 自己制作或可信的地图，希望启动较快、资源开销较小 |
| 独立 Docker | 希望地图之间更好地隔离，并单独控制资源 |

这里的“容器”是运行环境，不是地图工程文件。无需为了首次游玩而手动创建容器。

## 哪些参数值得关注

| 设置 | 作用 |
| --- | --- |
| 玩家上限、房间上限 | 限制同时进入的人数和房间数量 |
| 空闲回收时间 | 长时间无人后释放运行资源 |
| 资源组 | 控制地图能使用的 CPU、内存等资源 |

先保留默认值，观察实际使用后再调整。配置过低可能启动失败，过高则可能影响同一服务器上的其他地图。

保存配置后，在没有玩家在线时重启对应地图运行环境，让修改生效。不要直接删除地图包。

## “销毁”是什么意思

销毁会结束当前运行环境和在线游戏，不等于删除已安装地图。未保存的临时进度可能丢失，操作前先通知玩家。

地图启动失败时，先查看错误提示、服务器可用内存和磁盘空间，再到[常见问题](/operations/troubleshooting)排查。
