# 容器与资源管理

容器管理用于查看正在运行的地图，并决定地图使用共享 Node 进程还是独立 Docker 容器。配置可以按地图组统一应用，也可以细化到单张地图。

## 运行方式

### 共享 Node

多个地图运行时由共享服务管理。

优点：

- 启动较快
- 空闲资源占用较低
- 适合开发测试和可信地图

注意：

- 隔离程度低于独立 Docker
- 单个地图的异常更可能影响共享运行时
- 不适合运行来源不明或资源消耗不可控的地图

### 独立 Docker

每个地图或房间使用独立容器。独立容器归入 `box-local-engine-runtime` Compose 项目，容器名会包含地图 ID 和房间信息，方便排查。

优点：

- 进程与资源隔离更清晰
- 可以单独限制 CPU、内存、网络和进程数
- 容器日志和生命周期更容易定位

注意：

- 创建速度比共享 Node 慢
- 会产生更多容器和系统开销
- 需要为 Docker 保留更多磁盘和内存

## 按地图组或单图配置

| 方式 | 效果 |
| --- | --- |
| 地图组 | 主地图和全部副地图使用同一配置 |
| 单个地图 | 主地图和副地图分别配置 |

“单个地图”会显示地图组中的全部地图。适合副地图需要不同资源、玩家上限或隔离方式的情况。

## 地图容器配置

创建或编辑配置时，可以设置：

- 配置对象：地图组或单个地图
- 运行方式：共享 Node 或独立 Docker
- 玩家上限
- 房间上限
- 空闲回收时间
- 资源组

选择资源组后，CPU、内存和网络限制来自资源组，不需要在地图配置中重复填写。

## 资源组

资源组用于复用容器资源设置。一组完整配置可以包含：

| 设置 | 作用 |
| --- | --- |
| CPU 核数 | 限制容器可使用的 CPU |
| 内存上限 | 限制容器最大内存 |
| 网络策略 | 控制地图服务端运行时的网络访问能力 |
| 容器进程上限 | 限制容器内可创建的进程数量 |
| 出网带宽 | 限制容器对外发送数据的速率 |
| 资源说明 | 说明适用地图和使用目的 |

网络策略只控制服务端地图运行时所在容器的网络，不会自动限制玩家浏览器中执行的客户端代码。

可以创建多个资源组，例如：

| 名称 | 适用场景 |
| --- | --- |
| 轻量 | 小型大厅、低并发地图 |
| 标准 | 普通多人地图 |
| 高性能 | 脚本复杂或人数较多的地图 |
| 无外网 | 不需要访问公网的地图 |

删除资源组前，应先确认没有地图配置正在使用。正在使用的资源组不能直接删除。

## 当前资源使用

容器列表会同时显示当前使用量与配置上限，例如：

```text
CPU 0.35 / 2 核
内存 420 MB / 2048 MB
```

当前使用量来自运行时采样，上限来自资源组或默认环境配置。没有单独选择资源组时，仍会使用系统默认限制，不代表完全无限制。

## 重启、销毁与空闲回收

- **重启**：停止并重新创建当前地图运行时，适合配置变更后应用新限制。
- **销毁**：立即停止并移除当前运行时；不会删除已安装地图包。
- **空闲回收**：地图无人并超过设置时间后自动销毁运行时，再次进入时重新创建。

运行中的容器列表只提供与当前状态相符的操作。例如已启动的地图容器可以显示“销毁”，不会重复显示“启动”。

## 调整资源的建议

1. 先观察当前 CPU 和内存峰值。
2. 为正常峰值保留余量。
3. 遇到 OOM 时先检查脚本和资源泄漏，再决定是否提高内存。
4. 为不需要公网的地图选择限制外网的网络策略。
5. 不要给所有地图统一设置过高上限。
6. 修改后重启地图运行时，并重新执行多人测试。

## 排查独立容器

使用 Docker 查看运行时容器：

```bash
docker ps --filter label=com.docker.compose.project=box-local-engine-runtime
```

查看某个容器日志：

```bash
docker logs <容器名称>
```

如果后台没有显示已经启动的容器，先确认当前后台连接的是同一个 Docker Engine，再检查玩家服务是否有权限访问 Docker Socket。
