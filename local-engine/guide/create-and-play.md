# 创作、预览与发布

本地引擎将“可编辑工程”和“只读游玩包”分开管理。Creator 负责创作、预览和发布，Play 负责安装发布后的地图并运行房间。

## 认识两种文件

| 文件 | 用途 | 可以在哪里使用 |
| --- | --- | --- |
| `.boxproject` | 可继续编辑的地图工程 | Creator |
| `.boxplay` | 发布后的只读地图游玩包 | Play / 玩家管理后台 |

两种文件不能混用。不能把 `.boxproject` 当成游玩包导入 Play，也不能在 Creator 中直接编辑 `.boxplay`。

## 地图组

一个地图组包含：

- 一个主地图
- 零到多个副地图
- 地图组共用资源
- 地图组数据空间

主地图通常作为玩家进入地图组时的起点。副地图可以用于大厅、关卡、战斗房间或其他独立场景。

## 1. 创建地图工程

1. 在启动器中启动创作端。
2. 打开 Creator。
3. 新建地图工程，填写名称和基本信息。
4. 创建主地图。
5. 按需要添加副地图。
6. 进入 Arena 编辑地图内容。

Arena 的场景、UI、代码和发布操作请阅读 [Arena 编辑器用户手册](https://docs.dao3.fun/arena/)。

## 2. 制作模型

需要自定义模型、皮肤或动画时：

1. 打开 VOXA。
2. 新建或导入模型。
3. 完成部件、体素、骨骼和动画编辑。
4. 保存并在地图工程中使用资源。

具体操作请阅读 [Voxa 编辑器用户手册](https://docs.dao3.fun/voxa/)。

## 3. 本地预览

编辑过程中使用 Creator 的预览功能启动地图运行时。预览前检查：

- 地图脚本可以正常编译。
- 主地图设置正确。
- 需要的资源已经保存。
- Creator 运行时端口没有被占用。

预览用于创作阶段调试，不等同于最终 Play 环境。正式发布前仍应在游玩端完整测试。

## 4. 发布游玩包

在 Creator 中选择地图组并发布，生成 `.boxplay` 文件。发布包包含运行所需的地图快照、脚本和资源，但不包含 Creator 的可编辑工程源文件。

发布前建议：

1. 保存全部地图和资源。
2. 检查主地图与副地图关系。
3. 清理无用资源。
4. 完成多人进入和传送测试。
5. 确认客户端脚本不包含任何秘密。

## 5. 导入游玩包

1. 启动游玩端。
2. 使用服主管理密钥登录玩家管理后台。
3. 打开“游玩管理 → 游玩地图”。
4. 选择导入地图。
5. 选择 `.boxplay` 文件。
6. 在地图包预览中检查地图、脚本、图片、音频和其他资源。
7. 确认内容后完成导入。

地图包预览不会执行地图脚本。它用于在安装前检查包内内容。

如果提示“地图 ID 无效”，确认文件是当前版本 Creator 正常发布的 `.boxplay`，没有修改包内清单，也没有把展示名称当成永久地图 ID。

## 6. 配置地图运行方式

导入后，可以在“容器管理 → 地图容器配置”中选择配置对象：

- **地图组**：主地图和副地图共享一份配置。
- **单个地图**：每张地图可以使用独立配置。

可配置内容包括：

- 共享 Node 或独立 Docker
- 玩家上限
- 房间上限
- 空闲回收时间
- 资源组

如果副地图需要不同的 CPU、内存或隔离方式，应选择“单个地图”。

## 7. 进入地图测试

打开 Play，使用测试玩家登录并进入地图。至少测试：

- 首次进入主地图
- 多名玩家同时进入
- 从主地图传送到副地图
- 创建多个房间
- 玩家退出后的房间回收
- 服务重启后的地图可用性

地图内无人并超过设置的空闲回收时间后，对应地图运行时或独立容器会被回收。再次进入时会重新创建。

## 更新地图

修改工程后重新发布 `.boxplay`，再在游玩地图中执行更新。更新前：

1. 备份重要数据。
2. 确认新旧地图 ID 和地图组关系。
3. 避免在有玩家在线时直接替换。
4. 更新后重新测试登录、传送、存档和多人房间。

删除主地图对应的地图组会影响整个地图组。副地图列表中不会提供等价的“删除全部”操作。
