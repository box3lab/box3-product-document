# 访问范围与端口

本地引擎使用统一的访问范围。选择本机、局域网或公网后，所有业务服务都按同一范围生成访问地址，各服务仍使用独立端口。

## 本机模式

本机模式只监听或生成当前设备可访问的地址：

```text
http://127.0.0.1:<端口>
```

适合：

- 个人创作
- 本机功能测试
- 不需要其他设备访问的环境

本机模式最简单，也最不容易意外暴露管理功能。

## 局域网模式

局域网模式允许同一内网或 VPN 中的设备访问。其他设备使用运行本地引擎电脑的局域网 IP，例如：

```text
http://192.168.1.20:3121
```

无法访问时检查：

1. 两台设备是否在同一网络。
2. 服务是否正在运行。
3. 系统防火墙是否允许对应端口。
4. 路由器是否启用了客户端隔离。
5. 地址是否填写了正确的局域网 IP。

## 公网模式

公网模式使用公网 IP 或域名。设置时只填写主机部分：

```text
game.example.com
```

不要填写：

```text
https://game.example.com:3121/path
```

协议、端口和路径由实际访问方式或反向代理配置决定。

## 默认端口

| 端口 | 服务 | 公网建议 |
| ---: | --- | --- |
| `3121` | Play | 玩家需要访问时开放 |
| `3123` | VOXA | 仅向可信创作者开放 |
| `3124` | 玩家管理 | 不直接公开管理接口 |
| `3125` | 登录页面 | 使用内置登录页时开放 |
| `3127` | Creator | 仅向可信创作者开放 |
| `3130` | Linux Web 管理端 | 使用 HTTPS、VPN 或 IP 白名单保护 |
| `5432` | 内置 PostgreSQL | 不开放 |
| `6379` | 内置 Redis | 不开放 |

端口可以修改。修改后，以服务总览显示的地址为准。

## 云服务器安全组

云服务器通常同时存在两层限制：

1. 云厂商安全组。
2. Linux 系统防火墙。

安全组放行只代表网络可以到达服务器，不代表服务已经启动。端口仍无法访问时，应同时检查容器、监听地址和系统防火墙。

不要一次性开放全部端口。只开放玩家确实需要访问的 Play 和登录端口，Creator、VOXA 和管理端应限制来源。

## 域名和 HTTPS

面向公网时，建议使用 Nginx、Caddy 或其他反向代理提供 HTTPS。反向代理应：

- 为 Play 和登录页配置可信 TLS 证书。
- 为管理端增加来源限制或额外认证。
- 保留 WebSocket 升级请求。
- 正确转发客户端地址。
- 不代理 Docker Socket、PostgreSQL 或 Redis。

不同服务可以使用不同子域名，例如：

```text
play.example.com
login.example.com
creator.example.com
admin.example.com
```

## 修改端口

修改前先检查端口是否占用：

```bash
# Linux
ss -lntp

# macOS
lsof -nP -iTCP -sTCP:LISTEN
```

保存端口后重启相关服务。浏览器收藏、反向代理、安全组和登录回跳地址也要同步更新。

## 常见网络问题

| 现象 | 常见原因 |
| --- | --- |
| 本机能开，其他设备打不开 | 仍使用本机模式、防火墙阻止或地址使用了 `127.0.0.1` |
| 公网 IP 打不开 | 安全组未放行、服务未监听公网或运营商没有公网入站能力 |
| 页面能开，登录后跳转失败 | 登录回跳地址或公开地址配置不一致 |
| HTTPS 页面接口报错 | 反向代理漏配接口路径、WebSocket 或转发头 |
| 端口保存后启动失败 | 端口被其他程序占用 |
