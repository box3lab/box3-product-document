# 局域网与公网访问

所有访问地址都在“**数据配置 → 访问设置**”中配置。保存后，以服务卡片显示的最终地址为准。

## 只在自己电脑上使用

选择“**本机**”。浏览器和引擎运行在同一台电脑上即可，不需要域名或证书。

`127.0.0.1` 只能指向正在使用的这台电脑，不能发给其他玩家。

## 同一局域网的设备连接

1. 确认设备在同一 Wi-Fi、内网或可互通的 VPN 中。
2. 选择“**局域网**”，核对显示的是引擎电脑的局域网 IP。
3. 保存配置，重新启动受影响的服务。
4. 让其他设备使用显示的 Play 地址，例如 `http://192.168.1.20:3121`。

打不开时检查电脑防火墙。不同网络的玩家不能直接使用这个内网地址。

## 公网：先准备域名和证书

1. 准备可以从外网访问的服务器。
2. 将需要使用的域名解析到服务器公网 IP。
3. 准备覆盖该域名的 HTTPS 证书和私钥。
4. 在安全组和系统防火墙中放行最终使用的入口端口，HTTPS 通常是 `443`。

域名解析只负责把域名指向服务器，**不会自动配置 HTTPS 或启动网站**。

## 方式一：公网共用地址

适合首次开服：多个服务共用一个域名，用不同路径区分。

1. 选择“**公网（共用地址）**”。
2. 共用公网地址填写 `https://engine.example.com`，上传对应证书和私钥。
3. 为各服务填写不同的入口路径，例如：

| 服务 | 入口路径 | 最终地址示例 |
| --- | --- | --- |
| Play | `/play` | `https://engine.example.com/play` |
| Creator | `/creator` | `https://engine.example.com/creator` |
| VOXA | `/voxa` | `https://engine.example.com/voxa` |
| 玩家管理后台 | `/admin` | `https://engine.example.com/admin` |
| 登录页面 | `/login` | `https://engine.example.com/login` |

4. 保存配置，按提示安装并启动内置 Nginx，再次保存应用公网配置。
5. 从服务入口逐个检查页面能否打开，再把 **Play 的完整地址**发给玩家。

如果配置了 `/play`，只打开 `https://engine.example.com` 可能返回 404，这是没有给根路径分配页面。需要直接打开域名就进入 Play 时，可以将 Play 的入口路径留空；同一入口下不能给多个服务都留空。

## 方式二：公网独立地址

适合已有多个域名、或需要分别设置各服务入口的服主。

1. 选择“**公网（独立地址）**”。
2. 分别填写服务地址，例如 Play 用 `https://play.example.com`，登录页面用 `https://login.example.com`。
3. 为各个 HTTPS 地址配置匹配的证书和私钥。
4. 保存并应用，确认所有需要使用的入口都能访问。

也可以按界面支持的格式使用不同端口。**登录门户、Play 和 Creator 不必使用同一个域名**；请同步更新这些组件，定制登录页面时也要使用配套版本。

需要更换登录页面时，按[登录门户与模板](/guide/login-portal)配置，不要把模板仓库地址当作登录地址填写。

## 修改后怎么确认

- 使用卡片显示的完整地址，保留 `https://`、端口和入口路径。
- 用玩家账号登录，再打开 Play；需要创作时也检查 Creator。
- 地址改动后，重新登录；玩家启动器里保存的服务器地址也要更新。
- 提示配置已保存、但入口尚未生效时，先启动 Nginx，再次保存应用。

外部 Nginx 属于高级配置；已经有反向代理的服主可按管理器生成的配置接入。首次部署建议使用内置模式。
