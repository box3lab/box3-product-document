# 安全建议

本地引擎包含地图脚本、玩家账号、管理后台、数据库和 Docker 管理能力。正式对外提供服务前，应完成最基本的网络、账号和数据保护。

## 保护管理密钥

以下内容都属于秘密：

- Linux Web 管理端登录密钥
- 服主管理密钥
- 管理员密码
- CLI Token
- 数据库密码和连接串
- 服务内部签名密钥
- Cookie 和会话令牌

不要把秘密放进：

- Git 仓库
- 地图客户端或服务端脚本
- 浏览器前端代码
- 截图和教学视频
- 工单和公开聊天记录
- 未脱敏的日志

怀疑泄露时，应立即轮换密钥、撤销令牌并检查审计记录。

## 最小权限

不要让所有管理员都使用 owner。建议：

1. 每位管理员创建独立账号。
2. 按职责创建权限组。
3. 只需要查看时不要授予编辑权限。
4. 不参与管理时立即停用账号。
5. 定期检查权限组影响范围。
6. 高风险操作要求再次输入管理员密码。

编辑权限会依赖对应查看权限，这是正常的权限关系。

## 网络边界

公网环境只开放必要端口：

- Play 和登录页可以面向玩家开放。
- Creator 和 VOXA 只向可信创作者开放。
- 玩家管理和 Linux Web 管理端应使用 HTTPS、VPN 或 IP 白名单。
- PostgreSQL、Redis 和 Docker Socket 不能暴露到公网。

云服务器安全组和系统防火墙都需要配置。

## 使用 HTTPS

公网 HTTP 无法保护密码、Token 和 Cookie。正式部署应在反向代理配置 TLS 证书，并将 HTTP 重定向到 HTTPS。

反向代理还应限制请求大小、设置合理超时，并保留 WebSocket 连接所需的升级头。

## 地图脚本安全

服务端地图脚本运行在隔离运行时中，可以通过资源组限制 CPU、内存、网络、进程数和带宽。对于来源不明或需要更强隔离的地图，使用独立 Docker。

客户端脚本运行在玩家浏览器中：

- 玩家可以查看和修改收到的客户端代码。
- 客户端代码不能保存秘密。
- 胜负判定、奖励和权威存档应由服务端完成。
- TypeScript 类型声明不会形成安全沙箱。

资源组中的网络策略控制服务端容器，不会自动限制玩家浏览器的客户端脚本。

## 数据库安全

- 使用长且唯一的数据库密码。
- 内置数据库保持绑定 `127.0.0.1`。
- 外部数据库限制来源 IP。
- 公网数据库连接启用 TLS。
- 定期创建 `pg_dump` 或快照。
- 不要使用数据库超级用户运行普通业务。

## Docker 安全

Docker Socket 等同于主机级管理权限。只有启动器和需要管理地图容器的受信任服务可以访问。

不要：

- 把 `/var/run/docker.sock` 暴露到网络
- 让地图脚本直接访问 Docker API
- 随意使用特权容器
- 从不可信来源导入镜像

## 地图包检查

导入 `.boxplay` 前，使用预览检查：

- 地图数量和名称
- 服务端与客户端脚本
- 图片、音频和其他资源
- 发布来源和地图 ID

只导入可信来源的地图包。地图包预览不执行脚本，但安装并运行后脚本会在对应运行环境执行。

## 安全检查清单

- [ ] owner 密钥没有共享给普通管理员。
- [ ] 每位管理员使用独立账号和最小权限组。
- [ ] 公网入口已经使用 HTTPS。
- [ ] 管理端限制了访问来源。
- [ ] PostgreSQL、Redis 和 Docker Socket 未向公网开放。
- [ ] CLI Token 可以追踪并按需撤销。
- [ ] 高风险操作可以在审计记录中找到。
- [ ] 文件数据和 PostgreSQL 都有可恢复的备份。
- [ ] 不可信地图使用独立 Docker 和合理资源限制。
