# 安全建议

对外开放服务前，按以下步骤检查网络、账号、地图和数据安全。

## 1. 保管密钥

密钥包括管理端和服主管理 Token、管理员密码、CLI Token、数据库密码、Cookie 和会话令牌。

- 不要将密钥提交到 Git、写入地图脚本或前端代码，也不要放进截图和公开日志。
- 怀疑泄露时，立即更换密码、撤销 Token，并检查安全记录。

## 2. 限制管理员权限

1. 每位管理员使用独立账号，不共享 owner 密钥。
2. 按职责创建权限组，只授予所需的查看或编辑权限。
3. 人员不再参与管理时停用账号。
4. 定期检查权限组和高风险操作记录。

## 3. 控制网络入口

- 只开放必要端口；云安全组和系统防火墙都要检查。
- Play 与登录页面可按需要面向玩家开放。
- Creator、VOXA、玩家管理和 Linux Web 管理端应限制在可信网络，或使用 HTTPS、VPN、IP 白名单。
- 不要将 PostgreSQL、Redis 或 Docker Socket 暴露到公网。

公网部署需配置 TLS 证书并将 HTTP 重定向到 HTTPS。反向代理应保留 WebSocket 升级头，并设置合理的请求大小和超时。

## 4. 保护地图运行环境

1. 只导入可信来源的 `.boxplay`，导入前检查地图包预览。
2. 按地图可信度和资源需求选择共享 Node 或独立 Docker。
3. 使用资源组限制服务端脚本的 CPU、内存、网络、进程数和带宽。
4. 不要让地图脚本访问 Docker API，也不要随意启用特权容器。

地图包预览不会执行脚本；安装并运行后，脚本会在对应运行环境执行。客户端脚本在玩家浏览器运行，不能保存秘密，也不能负责权威的胜负判定、奖励或存档。

## 5. 保护数据库

- 为数据库设置长且唯一的密码。
- 内置 PostgreSQL 保持绑定 `127.0.0.1`；外部数据库限制来源 IP 并启用 TLS。
- 使用 `pg_dump` 或快照定期备份。
- 不要删除 PostgreSQL 数据卷来处理登录或连接问题。
