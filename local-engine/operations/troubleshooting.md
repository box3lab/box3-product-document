# 常见问题

排障时先记录发生时间、操作步骤、页面错误、服务状态和相关日志。不要通过删除数据目录或 Docker 卷进行尝试。

## 页面打不开

按顺序检查：

1. Docker 是否运行。
2. 对应服务是否显示“运行中”。
3. 浏览器地址和端口是否正确。
4. 访问范围是否与使用场景一致。
5. 防火墙和云安全组是否放行。
6. 端口是否被其他程序占用。

Linux 查看状态：

```bash
cd /opt/box3-engine
./status.sh
docker ps
```

## 页面刷新后显示 404

如果首页可以打开，但刷新带有页面路径或查询参数的地址后出现 404，通常是反向代理没有把前端路由回退到入口页面。

检查代理是否把未知前端路径交给对应应用处理，而不是直接查找同名静态文件。

## 接口返回 503

`503 Service Unavailable` 通常表示前端代理找不到玩家服务，或玩家服务依赖未就绪。

检查：

```bash
./logs.sh player-service
./logs.sh managed-postgres
```

常见原因：

- Player Service 没有启动
- PostgreSQL 连接失败
- 数据库迁移失败
- 玩家服务健康检查没有通过
- Docker Socket 权限不足，容器管理接口不可用

## 管理员登录尝试过多

连续输入错误密码会触发临时限流。停止继续尝试，等待限制时间结束后再使用正确密码登录。

同时检查：

- 输入的是管理员密码还是服主管理密钥
- 账号是否已停用
- 浏览器是否仍保存旧登录状态
- 是否有其他设备持续使用错误密码请求

停用账号应显示账号已停用，不应通过反复尝试密码解决。

## 玩家服务无法连接 PostgreSQL

检查数据库地址、端口、数据库名、用户名、密码和 SSL 设置。

内置数据库已有数据卷但原 `.env` 丢失时，不要生成一套新随机凭据连接旧卷。应恢复创建该数据卷时使用的配置。

## 导入地图提示地图 ID 无效

确认：

- 文件扩展名是 `.boxplay`
- 文件来自当前兼容版本 Creator 的发布功能
- 没有手工修改压缩包或清单
- 填写的是永久地图 ID，而不是地图名称、版本号或展示 ID
- 主地图和副地图的地图组关系完整

重新从 Creator 发布一次，再使用地图包预览检查内容。

## 查看地图包偶尔失败

先确认文件仍然存在且上传完成，再检查：

- 文件是否过大或传输中断
- 磁盘临时空间是否足够
- 地图包清单是否完整
- 包内资源路径是否异常
- Play 或玩家服务日志中是否有解析错误

不要重复点击导入。保存一次失败请求的时间和完整错误信息后再排查。

## 容器列表不显示已启动地图

1. 确认地图确实创建了运行时，不只是 Play 主服务启动。
2. 确认后台与桌面启动器连接同一个 Docker Engine。
3. 检查玩家服务访问 Docker Socket 的权限。
4. 查看运行时 Compose 项目：

```bash
docker ps --filter label=com.docker.compose.project=box-local-engine-runtime
```

5. 检查地图 ID、房间号和容器标签是否完整。

## 独立 Docker 无法启动

检查：

- Docker 可用磁盘空间
- 资源组 CPU 和内存值是否合法
- 网络策略和带宽设置
- 容器进程上限
- 地图镜像是否存在
- 玩家服务是否可以创建 Docker 容器

如果容器启动后立即退出，使用 `docker logs <容器名>` 查看原因。

## 重启地图返回 503

重启地图会请求玩家服务创建或替换运行时。出现 503 时先查看玩家服务日志，并确认：

- Player Service 健康
- PostgreSQL 可用
- Docker Socket 可访问
- 地图配置和资源组仍存在
- 当前镜像版本一致

## 内存不足或容器被 OOM 终止

先检查地图脚本是否持续创建对象、计时器或缓存，再观察峰值内存。确认没有明显泄漏后，可以提高资源组内存上限并重启地图运行时。

不要只把所有资源组改成无限或极高上限，这会让单个异常地图影响整台服务器。

## CPU 或内存上限来源不明

页面显示的上限来自：

1. 地图选择的资源组；或
2. 没有选择资源组时的默认环境配置。

因此“未选择资源组”不表示没有上限。

## Linux 管理密钥忘记

在默认安装目录中执行：

```bash
cd /opt/box3-engine
sed -n 's/^BOX_SERVER_MANAGER_TOKEN=//p' .env
```

该命令只读取 Linux Web 管理端密钥。服主管理后台使用的是 `BOX_PLAY_ADMIN_TOKEN`，两者不要混用。

## 升级后许可证失效

检查旧 `.env` 中的安装密钥和完整 `license/` 目录是否保留。设备 ID 变化时，先恢复原配置，不要立即删除并重新初始化所有数据。

## 收集排障信息

向维护者反馈前准备：

- 本地引擎版本
- 操作系统与 CPU 架构
- Docker 和 Compose 版本
- 出错时间和复现步骤
- 相关服务状态
- 已脱敏的容器日志
- 浏览器请求 URL、方法、状态码和返回消息

不要发送 `.env`、Token、数据库密码、Cookie、玩家 IP 或未脱敏的数据包。
