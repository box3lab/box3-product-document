# 升级本地引擎

升级前先完成文件和 PostgreSQL 备份。升级程序和镜像不等于迁移数据，关键配置和数据目录必须保留。

## 桌面版升级

1. 在启动器中停止全部业务服务。
2. 导出重要地图与备份。
3. 备份 PostgreSQL。
4. 退出旧启动器。
5. 下载与当前系统和架构一致的新版本。
6. 完整解压到新目录，不要覆盖压缩包内运行。
7. 打开新启动器并按提示导入新镜像。
8. 确认许可证、配置和数据路径仍然正确。
9. 启动服务并进行验证。

桌面启动器的持久数据位于系统应用数据目录。正常替换应用程序不会删除该目录，但升级前仍应备份。

## Linux 一键升级

Linux 一键安装支持重复执行。使用相同命令即可更新：

```bash
curl -fsSL https://assets.box3.fun/local-engine/install.sh | sudo bash
```

安装器会：

- 下载当前最新发行包
- 更新启动器和业务镜像
- 保留现有 `.env`
- 保留许可证、地图、模型和备份
- 保留 PostgreSQL 与 Redis 数据卷
- 重建升级前正在运行的业务服务

原本未运行的业务服务不会被自动启动。

## 安装指定版本

需要固定版本时：

```bash
curl -fsSL https://assets.box3.fun/local-engine/install.sh -o install.sh
sudo BOX3_VERSION=0.2.0 sh install.sh
rm install.sh
```

不要把不同版本的单个镜像、前端文件或 Compose 文件拼在一起使用。启动器与业务镜像应来自同一发行版本。

## 升级保留什么

正常升级应保留：

- 安装配置和安全密钥
- 许可证及设备安装标识
- Creator 工程
- Play 地图库
- VOXA 模型数据
- 启动器备份
- PostgreSQL 数据卷
- Redis 数据卷

升级不应通过删除 Docker 卷来“清理环境”。删除卷会造成数据丢失。

## 升级后的检查

升级后依次检查：

1. 启动器显示的版本正确。
2. 许可证仍然有效。
3. PostgreSQL 连接正常。
4. 所有需要的服务健康。
5. Creator 工程可以打开和保存。
6. VOXA 模型可以读取。
7. Play 地图可以进入。
8. 玩家和管理员可以登录。
9. 权限组、CLI 令牌和审计记录仍存在。
10. 独立 Docker 地图可以启动、重启和销毁。

## 升级失败

如果升级后服务无法启动：

1. 不要删除数据卷。
2. 保存当前日志。
3. 检查启动器与镜像版本是否一致。
4. 检查 `.env` 是否仍是升级前的配置。
5. 检查许可证目录和安装密钥。
6. 检查数据库迁移错误。
7. 在确认兼容的前提下恢复旧版本程序和镜像。

回退程序前先保留升级后的数据库备份。数据库已经执行新版本迁移时，直接使用旧程序可能不兼容。
