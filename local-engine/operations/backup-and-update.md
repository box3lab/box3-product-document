# 备份与更新

更新版本、迁移服务器、删除地图前，先保存备份。把备份保留在原设备之外，避免磁盘故障时一起丢失。

## 哪些数据需要备份

| 内容 | 建议方式 |
| --- | --- |
| 可以继续编辑的作品 | 在 Creator 导出 `.boxproject` |
| 已发布、可导入游玩的版本 | 保留 `.boxplay` 游戏包 |
| 管理器中的工程、游玩地图、模型与环境配置 | 在“数据与备份”创建文件备份 |
| 玩家账号、权限、数据库中的游戏存档 | 单独备份 PostgreSQL |

**管理器文件备份和工程包都不包含 PostgreSQL 数据库。** 如果使用云数据库，可启用服务商的自动备份；自行部署时，请维护者安排数据库备份。使用外部资源存储的地图，也要保留对应资源。

## 手动创建备份

1. 尽量在没有玩家在线、没有人编辑作品时操作。
2. 打开部署管理器的“**数据与备份**”。
3. 点击“**立即备份**”，等待文件出现在列表中。
4. 将需要保留的备份导出或下载到其他安全位置。

备份可能包含环境配置和密钥，不要上传到公开网盘或发到群聊。

## 自动备份作品

在“**数据配置 → 自动备份**”中启用备份，设置间隔、每张地图保留份数和保留天数，保存。

自动备份按计划导出地图组工程，包含地图、资源和地图配置，**不包含玩家账号或数据库存档**。达到保留上限后，较早的自动备份会被清理。

## 恢复备份

1. 先备份当前状态，确认选择的是需要恢复的文件。
2. 在“**数据与备份 → 导入备份**”中导入，再按页面提示恢复。
3. 仔细阅读恢复范围；只有确实要恢复旧连接和旧地址时，才选择还原环境配置。
4. 恢复完成后检查数据配置，按需要重新启动服务。
5. 验证作品、游玩地图和登录是否正常。数据库需要使用自己的备份另行恢复。

只恢复某个作品时，优先在 Creator 导入 `.boxproject`，不必恢复整个部署环境。

## 更新引擎

1. 先完成文件与数据库备份，记录当前版本。
2. 在部署管理器“**关于 → 检查更新**”中查看更新说明，按提示下载并更新。
3. 等待更新和服务启动完成，不要中途关闭 Docker。
4. 用玩家账号检查登录、进入地图和存档；创作环境还需打开旧作品预览。

不支持在线更新或需要换设备时，下载新的正式安装包，按提示迁移；不要直接删除旧数据目录。引擎与玩家启动器独立更新，登录门户使用自定义镜像时也需同步更新配套版本。

正式版和带 `staging` 后缀的预发布版是不同更新渠道；带 `dev` 的开发包不检查线上更新。普通使用请选择正式版。
