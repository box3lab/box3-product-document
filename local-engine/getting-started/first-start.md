# 首次启动

安装完成后，需要依次完成许可证、数据服务、访问范围和安全密钥配置。建议不要跳过步骤。

## 1. 打开启动器

桌面版直接打开 BOX3 Engine Launcher。Linux 服务器打开安装完成时显示的管理地址，并输入管理端登录密钥。

如果页面无法打开，先检查 Docker 是否运行，再查看[常见问题](/operations/troubleshooting)。

## 2. 安装许可证

1. 打开“许可证管理”。
2. 复制设备 ID。
3. 申请与该设备 ID 对应的 `.boxlic` 文件。
4. 点击导入并选择许可证文件。
5. 确认状态、有效期和授权范围正确。

许可证无效或过期时，启动器不会启动业务服务。

## 3. 配置 PostgreSQL

打开“数据配置”，选择 PostgreSQL 模式。

### 内置 PostgreSQL

适合第一次使用：

1. 选择“内置 PostgreSQL”。
2. 等待启动器下载镜像。
3. 启动器会自动生成数据库账号和密码。
4. 保存配置并执行连接检查。

内置数据库只绑定本机回环地址，不应对公网开放。

### 外部 PostgreSQL

适合已有数据库服务：

1. 填写主机、端口、数据库名、用户名和密码。
2. 根据数据库要求设置 SSL。
3. 点击连接测试。
4. 测试成功后保存。

不要在多个不相关的本地引擎实例之间混用同一数据库，除非你明确设计了数据隔离。

## 4. 配置 Redis

Redis 有三种模式：

- 不启用
- 内置 Redis
- 外部 Redis

第一次使用可以选择内置 Redis，也可以关闭。Redis 不保存玩家、权限和地图脚本的永久数据。

## 5. 选择访问范围

访问范围只有一处设置，并统一作用于 Play、Creator、VOXA、玩家管理和登录页面。

### 本机

只有当前电脑访问。适合个人创作和单机测试。

### 局域网

同一内网或 VPN 中的设备可以访问。其他设备应使用运行本地引擎电脑的局域网 IP。

### 公网

填写公网 IP 或域名，不要包含 `http://`、`https://`、端口或路径。还需要放行每个实际使用的服务端口。

## 6. 检查端口

默认端口如下：

| 服务 | 端口 |
| --- | ---: |
| Play | `3121` |
| VOXA | `3123` |
| 玩家管理 | `3124` |
| 登录页面 | `3125` |
| Creator | `3127` |

如果端口已被其他程序占用，可以修改。修改后应使用“服务总览”显示的新地址。

Linux Web 管理端默认使用 `3130`，它不属于业务服务端口。

## 7. 保存安全密钥

启动器会使用多类随机密钥保护不同接口。Linux 安装器会自动生成；桌面版按页面要求创建或填写。

关键密钥必须满足页面显示的长度要求，并且彼此不同。不要使用简单密码，也不要把密钥提交到 Git。

特别注意：

- 管理端登录密钥用于 Linux Web 启动器。
- 服主管理密钥用于玩家管理后台 owner 登录。
- 两者不能互相替代。

## 8. 启动服务

在“服务总览”选择：

| 操作 | 启动内容 |
| --- | --- |
| 启动创作端 | Creator、VOXA 及所需依赖 |
| 启动游玩端 | Play、玩家管理、登录页面及所需依赖 |
| 启动全部服务 | 同时启动创作端和游玩端 |

首次启动需要创建容器，时间会比后续启动更长。等待所有服务显示健康后再打开页面。

## 9. 验证服务

依次检查：

1. Creator 可以打开并显示工程列表。
2. VOXA 可以打开并显示模型列表。
3. Play 可以打开地图大厅。
4. 登录页面可以注册或登录测试玩家。
5. 玩家管理可以使用服主管理密钥登录。

如果某个页面打开但接口返回 `503`，通常是依赖的玩家服务或数据库没有就绪。查看对应容器日志，不要反复删除数据卷。

## 10. 完成第一次使用

服务正常后，可以继续：

- 阅读[创建并游玩地图](/guide/create-and-play)。
- 阅读[玩家管理后台](/guide/player-admin)。
- 在正式导入数据前完成一次[备份与恢复](/operations/backup)演练。
